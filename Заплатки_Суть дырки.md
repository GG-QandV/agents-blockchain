## Суть дырки

| Сценарий                                                                  | Что происходит                                                                                                                                                                      |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Whitelist = узкий адрес (API-сервис, одна услуга)                         | Гап минимален: получатель ≈ назначение                                                                                                                                              |
| Whitelist = широкий мерчант (маркетплейс, у одного адреса тысячи товаров) | Агент в пределах лимита покупает **что угодно**: правила Δ контролируют «кому и сколько», но не «за что». Скомпрометированный/глючный агент легально сливает дневной лимит на мусор |

## Закрытие: Invoice-Binding (привязка к счёту мерчанта)

Принцип: μ авторизует не «перевод X адресу Y», а «оплату конкретного подписанного счёта».

```
Agent → мерчант: запрос покупки
Мерчант → Agent: SignedOffer { items[], category, amount, merchant_sig, ttl, offer_hash }
Agent → μ: intent { recipient, amount, offer }          ← вместо строки purpose
μ:  Ω → Δ-правила ПО ДАННЫМ ОФФЕРА (категории, SKU-маски) → проверка merchant_sig
    → платёж с offer_hash в calldata/memo/метаданных → Log хранит весь оффер
```

| Что даёт                                                                                   | Что НЕ даёт                                                                                                       |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| purpose перестаёт быть неверифицируемой строкой агента — это подписанные мерчантом позиции | Не защищает от лживого мерчанта (он подписывает свой же счёт) — но мерчант уже в whitelist, т.е. доверен на сумму |
| Δ получает новый класс правил: category_rules (allow: "saas,api", deny: "gambling")        | Не работает с мерчантами без подписанных офферов → для них деградация к старой модели + агрессивный лимит         |
| M9 показывает владельцу позиции счёта, а не слово агента (закрывает и вектор из RISK-M9-1) |                                                                                                                   |
| Спор/аудит: в логе доказательство «что именно было куплено»                                |                                                                                                                   |

**Рыночная опора (факт):** ровно эту связку стандартизируют агентские протоколы — x402 (HTTP 402 платёжный протокол: сервер сам присылает payment requirements), ACP (Agentic Commerce Protocol — OpenAI/Stripe: подписанный checkout), Visa/Mastercard trusted-agent схемы. Т.е. SignedOffer не экзотика, а формирующийся стандарт — μ должен его принимать, а не изобретать.
