# Архитектура Δ-Composer — локальный редактор правил Δ

## 1. Назначение и границы

Отдельная локальная программа: владелец создаёт/редактирует Δ (лимит, whitelist, порог) и подписанным артефактом передаёт в μ. **Не** трогает Value/ключи кошелька, **не** проводит платежи, **не** редактирует Ω (только просмотр потолка для контекста).

Почему отдельная прога, а не часть демона: разделение привилегий — компрометация редактора не даёт доступа к деньгам (подпись Δ всё равно требует биометрии через M4), а демон не тащит GUI-стек.

## 2. Схема

```
┌────────────────── Δ-Composer (GUI) ──────────────────┐
│ C1 UI-слой (просмотр Ω, форма Δ, diff)               │
│ C2 Validator (границы, канон адресов, схема)         │
│ C3 Draft Store (черновики, локально, без секретов)   │
│ C4 Export: DeltaProposal (CBOR, БЕЗ подписи)         │
└──────────────────────┬────────────────────────────────┘
                       │ файл/сокет: proposal
                       ▼
┌────────────────── μ-демон ────────────────────────────┐
│ M9: показ diff → биометрия → M4: подпись owner-ключом │
│ → M1.save → M5.append(DeltaChanged)                   │
└────────────────────────────────────────────────────────┘
```

**Ключевое решение защиты:** Composer готовит *предложение* (proposal), но подписывает и применяет только демон после биометрии с показом diff на своей стороне. Composer полностью недоверен по модели угроз — как агент в M8.

## 3. Модули Composer

| Модуль       | Функция                                                                                                                                                                          | LOC (~) |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| C1 ui        | Форма трёх правил; загрузка текущей Δ и Ω из μ (read-only через сокет демона); визуальный diff old→new                                                                           | 500     |
| C2 validator | daily_limit ≤ Ω.ceiling; адреса: EIP-55 чексумма + канонизация + chain_id; threshold ≤ limit; JSON Schema всей структуры; предупреждения («лимит = потолку», «пустой whitelist») | 150     |
| C3 drafts    | Черновики в локальном файле, plaintext допустим (Δ не секрет — секрет только подпись)                                                                                            | 100     |
| C4 export    | Сборка `DeltaProposal{new_delta, base_delta_hash, ts}` в CBOR → сокет демона                                                                                                     | 80      |

`base_delta_hash` = хеш текущей Δ, от которой правили: демон отклоняет proposal, если Δ уже изменилась (защита от TOCTOU — Time-Of-Check-Time-Of-Use, гонка «проверил одно, применил к другому»).

## 4. Кроссплатформенность (требование MVP)

| Вариант                                           | Оценка                                                                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tauri (Rust-ядро + системный WebView)** — выбор | Одна кодовая база Win/macOS/Linux; C2/C4 — тот же Rust-код, что валидация в демоне (общий crate = ноль расхождений правил); бинарь 3–10 МБ; не тащит Chromium |
| Electron                                          | Кроссплатформенно, но +150 МБ Chromium и шире поверхность атаки — избыточно для формы из трёх полей                                                           |
| Нативные ×3                                       | Три кодовые базы ради формы — неоправданно                                                                                                                    |
| CLI-утилита                                       | Добавить как второй фронтенд к тем же C2/C4 (~100 LOC): скрипты, headless, доверие «глазами по тексту»                                                        |

Общий crate `mu-policy` (типы Δ, валидация, канонизация адресов) линкуется и в демон, и в Composer — единственный источник правды о правилах.

## 5. Защита

| Угроза                                                                    | Контрмера                                                                                                                                                       |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подмена Composer'а целиком (троян)                                        | Не критично by design: подпись только в демоне после биометрии; **diff рендерит M9 из proposal, не доверяя UI Composer'а**                                      |
| Подмена адреса в буфере обмена (clipboard-malware — типовая крипто-атака) | При вставке адреса C1 показывает первые/последние 6 символов крупно + identicon (детерминированная картинка из хеша); финальная сверка — всё равно в диалоге M9 |
| TOCTOU между экспортом и подписью                                         | base_delta_hash в proposal                                                                                                                                      |
| Мусорный proposal валит демон                                             | Демон валидирует proposal тем же `mu-policy` + лимит размера 8 КБ + тот же парсер-fuzz, что M8                                                                  |
| Черновики как разведка (лимиты видны)                                     | Принять: Δ — не секрет; опц. шифрование черновиков ОС-хранилищем (DPAPI/Keychain) — флажок, не MVP-требование                                                   |
| Supply chain UI-зависимостей                                              | Webview-фронт без внешних JS-пакетов (vanilla/минимум), lockfile, сборка reproducible                                                                           |

## 6. Датафлоу

```
① C1: загрузить текущие Δ,Ω  ← демон (read-only endpoint, без секретов)
② владелец правит форму → C2 валидирует на каждый ввод
③ C3 автосохраняет черновик
④ «Отправить» → C4: DeltaProposal(CBOR) → сокет демона
⑤ демон: mu-policy.validate → M9 diff-диалог (данные из proposal) → биометрия
⑥ M4 подпись owner → M1.save → M5.append(DeltaChanged)
⑦ демон → Composer: Applied | Rejected{reason} → C1 показывает результат
```

## 7. Объём

~830 LOC Rust/TS + общий crate mu-policy (~150, вычитается из M3/M9) + CLI ~100. Файлов ~12. Отдельный security-аудит не требуется (недоверенный компонент) — аудит идёт на приёмную сторону демона (⑤).
