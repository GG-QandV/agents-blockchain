# SPEC: Δ-Composer v1.0 (MVP)

Статус: Draft для реализации • Дата: 2026-07-12 • Компонент системы μ-agentic MVP v3

---

## 1. Обзор

### 1.1. Назначение
Δ-Composer — локальное кроссплатформенное GUI/CLI-приложение для создания и редактирования политик Δ (daily_limit, whitelist получателей, confirm_threshold) μ-объекта. Composer формирует **неподписанное предложение** (DeltaProposal); подпись, показ финального diff и применение выполняет исключительно μ-демон (модули M9→M4→M1→M5).

### 1.2. Не входит в назначение (out of scope)
- Доступ к ключам кошелька и Value-слоту — запрещён архитектурно.
- Инициация платежей.
- Редактирование Ω (только read-only отображение для контекста).
- Управление жизненным циклом μ (выпуск/перевыпуск).
- Синхронизация/облако/сеть за пределы локального сокета демона.

### 1.3. Модель доверия
Composer — **недоверенный компонент**, эквивалентен агенту в модели угроз демона. Компрометация Composer не должна позволять изменить Δ без биометрии владельца в M9 и не даёт доступа к секретам. Все гарантии целостности — на приёмной стороне (демон).

## 2. Термины

| Термин | Значение |
|---|---|
| Δ (Delta) | Редактируемые владельцем политики: лимит/окно, whitelist, порог подтверждения |
| Ω (Omega) | Неизменяемый потолок возможностей μ; Composer читает, не пишет |
| DeltaProposal | CBOR-артефакт: новая Δ + привязка к базовой версии; без подписи |
| mu-policy | Общий crate (библиотека) типов и валидации Δ, линкуется в демон и Composer |
| TOCTOU | Time-Of-Check-Time-Of-Use — гонка между проверкой состояния и его использованием |
| EIP-55 | Стандарт чексуммирования Ethereum-адресов регистром букв |
| identicon | Детерминированная картинка из хеша для визуальной сверки адреса |

## 3. Требования

### 3.1. Функциональные (F)

| ID | Требование |
|---|---|
| F-01 | Загрузка текущих Δ и Ω из демона через read-only endpoint; работа невозможна без живого демона (кроме режима черновиков offline, см. F-08) |
| F-02 | Редактирование трёх правил Δ: daily_limit (u128 минорные единицы + отображение в человекочитаемой величине актива), whitelist (список адресов с label), confirm_threshold |
| F-03 | Валидация на каждый ввод (см. §7); блокировка экспорта при ошибках; предупреждения не блокируют |
| F-04 | Визуальный diff текущая Δ → новая Δ до экспорта |
| F-05 | Экспорт DeltaProposal в демон через локальный сокет; приём результата Applied/Rejected{reason} |
| F-06 | Управление whitelist: добавление адреса вставкой/вводом, label ≤ 64 символов, удаление, поиск; identicon и укрупнённые первые/последние 6 символов при вставке |
| F-07 | История применённых изменений: read-only список записей DeltaChanged из лога демона (через тот же endpoint) |
| F-08 | Черновики: автосохранение локально; offline-редактирование черновика допустимо, экспорт — только при живом демоне |
| F-09 | CLI-фронтенд с командами: `show`, `set-limit`, `wl-add`, `wl-rm`, `set-threshold`, `diff`, `propose` — на тех же C2/C4 |
| F-10 | Локализация: RU/EN, строки во внешнем ресурсе |

### 3.2. Нефункциональные (N)

| ID | Требование |
|---|---|
| N-01 | Платформы: Windows 10+, macOS 13+, Linux (glibc 2.31+); одна кодовая база |
| N-02 | Технология: Tauri 2.x (Rust-ядро + системный WebView); фронтенд без внешних JS-фреймворков (vanilla TS), zero runtime-CDN |
| N-03 | Размер дистрибутива ≤ 15 МБ; холодный старт ≤ 2 с |
| N-04 | Никакого сетевого трафика, кроме localhost/unix-socket к демону; исходящие соединения блокированы конфигурацией Tauri allowlist |
| N-05 | Без телеметрии; логи приложения — локальные, без адресов whitelist в plaintext на уровне INFO |
| N-06 | Reproducible build; lockfile для всех зависимостей; cargo-deny/audit в CI |
| N-07 | Доступность: полное управление с клавиатуры; масштабирование до 200% |

## 4. Архитектура

### 4.1. Компоненты

```
┌───────────────────────── Δ-Composer ─────────────────────────┐
│  C1 ui         WebView (vanilla TS) + Tauri commands         │
│  C2 validator  Rust, реэкспорт mu-policy                     │
│  C3 drafts     Rust: локальное хранилище черновиков          │
│  C4 transport  Rust: сокет-клиент демона, сборка proposal    │
│  C5 cli        Rust bin: те же C2/C4 без WebView             │
└───────────────────────────────────────────────────────────────┘
            │ unix socket / named pipe (протокол §6)
            ▼
        μ-демон: endpoint policy_ro / policy_propose
```

### 4.2. Общий crate `mu-policy` (единственный источник правды о правилах)

```rust
// линкуется в демон (M3, M9, endpoint) и в Composer (C2)
pub struct Delta { pub daily_limit: Amount, pub whitelist: Vec<WlEntry>, pub confirm_threshold: Amount }
pub struct WlEntry { pub address: CanonAddress, pub chain_id: u64, pub label: String /*≤64*/ }
pub struct OmegaView { pub max_ceiling: Amount, pub connectors: Vec<String>, pub operations: Vec<String> }

pub fn validate(new: &Delta, omega: &OmegaView) -> ValidationReport;   // §7
pub fn canon_address(input: &str, chain_id: u64) -> Result<CanonAddress, AddrErr>;
pub fn delta_hash(d: &Delta) -> Hash;                                   // SHA-256(canonical CBOR)
pub struct ValidationReport { pub errors: Vec<VErr>, pub warnings: Vec<VWarn> }
```

Правило: любое изменение логики валидации делается ТОЛЬКО в mu-policy; C2 и демон не имеют собственных проверок правил (кроме размера/формата транспорта).

### 4.3. Зависимости Composer

| Зависимость | Роль |
|---|---|
| tauri 2.x | Оболочка, IPC UI↔Rust, allowlist |
| mu-policy (внутр.) | Типы и валидация |
| ciborium (или эквив.) | CBOR |
| serde | Сериализация типов |
| interprocess (или эквив.) | Unix socket / named pipe |
| blockies-подобный генератор (внутр., ~60 LOC) | identicon без внешних crates |

Итого внешних: ≤ 5. Всё, что можно, — из workspace демона.

## 5. Форматы данных

### 5.1. DeltaProposal (CBOR, canonical form RFC 8949 §4.2)

```
DeltaProposal = {
  1: uint,          ; v — версия формата, =1
  2: Delta,         ; новая Δ (map, ключи int)
  3: bstr .size 32, ; base_delta_hash — delta_hash(текущей Δ, от которой правили)
  4: uint,          ; ts — unix-время создания proposal (сек)
  5: tstr .size (0..64) ; client — "composer/1.0" | "cli/1.0" (диагностика)
}
Delta = { 1: uint /*daily_limit*/, 2: [ * WlEntry ], 3: uint /*threshold*/ }
WlEntry = { 1: bstr .size 20 /*addr*/, 2: uint /*chain_id*/, 3: tstr /*label*/ }
```

Ограничения: |proposal| ≤ 8192 байт; |whitelist| ≤ 128 записей (MVP); label — UTF-8 NFC, без управляющих символов.

### 5.2. Черновик (локальный файл)

```
drafts/current.cbor  = { 1: Delta, 2: base_delta_hash|null, 3: ts_saved }
```
Черновики не секретны; опциональное шифрование ОС-хранилищем (Keychain/DPAPI/secret-service) — настройка `encrypt_drafts=true`, по умолчанию false. Ротация: хранится 1 текущий + 5 последних по времени.

## 6. Протокол Composer ↔ демон

Транспорт: unix socket `$MU_HOME/policy.sock` (права 0600) / Windows named pipe `\\.\pipe\mu-policy` (DACL: только текущий пользователь). Кадр: `len:u32 LE ‖ cbor(msg)`; таймаут чтения 5 с; демон обслуживает 1 соединение одновременно.

| Msg → демон | Ответ ← демон | Семантика |
|---|---|---|
| `GetPolicy{}` | `Policy{delta, delta_hash, omega_view, applied_history[≤50]}` | F-01, F-07; секретов и Value-полей в ответе нет |
| `Propose{DeltaProposal}` | `Accepted{ticket}` затем push `Result{Applied{new_hash}}` \| `Rejected{code, human_reason}` | Демон: размер→CBOR→mu-policy.validate→base_hash==current→M9 diff+биометрия→M4→M1→M5 |
| `Ping{}` | `Pong{daemon_version, mu_id}` | Health-check и привязка UI к конкретному μ |

Коды Rejected: `Stale` (base_hash не совпал — TOCTOU), `Invalid{VErr[]}`, `TooLarge`, `HumanDenied`, `HumanTimeout`, `Busy`, `Internal`.

Требование безопасности протокола: демон парсит Propose тем же hardened-парсером, что M8 (общий код кадрирования), и фаззится в том же CI-таргете.

## 7. Правила валидации (mu-policy.validate)

### 7.1. Ошибки (блокируют экспорт)

| Код | Правило |
|---|---|
| E-LIM-01 | daily_limit == 0 |
| E-LIM-02 | daily_limit > omega.max_ceiling |
| E-THR-01 | confirm_threshold > daily_limit |
| E-ADR-01 | Адрес: не hex-20-байт после канонизации |
| E-ADR-02 | EIP-55 чексумма присутствует и неверна (адрес целиком в lowercase/uppercase допускается с warning W-ADR-01) |
| E-ADR-03 | chain_id ∉ поддерживаемых демоном (из OmegaView/connectors) |
| E-ADR-04 | Дубликат (address, chain_id) в whitelist |
| E-LBL-01 | label > 64 символов или содержит управляющие/би-ди символы (U+202A..U+202E и т.п.) |
| E-STR-01 | Нарушение схемы CBOR/размеров §5.1 |

### 7.2. Предупреждения (не блокируют, показываются и логируются в proposal-diff)

| Код | Правило |
|---|---|
| W-LIM-01 | daily_limit == omega.max_ceiling («лимит равен потолку — Δ не добавляет защиты») |
| W-WL-01 | whitelist пуст («все получатели будут отклоняться») |
| W-THR-01 | confirm_threshold == 0 («каждый платёж потребует биометрии») |
| W-THR-02 | confirm_threshold == daily_limit («подтверждение фактически отключено ниже лимита») |
| W-ADR-01 | Адрес без EIP-55 (весь lower/upper) — принят, но рекомендована сверка |

## 8. Спецификация UI (C1)

### 8.1. Экраны

| Экран | Содержимое | Ключевые элементы |
|---|---|---|
| S1 Главный | Текущая Δ + карточка Ω (read-only: ceiling, коннекторы) | Кнопки: Править, История; индикатор связи с демоном и mu_id |
| S2 Редактор | Форма: лимит (поле+актив), порог, whitelist-таблица | Инлайн-валидация C2 на input; счётчик записей WL |
| S3 Добавить адрес | Поле адреса, chain, label | Крупно: первые/последние 6 символов; identicon; кнопка «вставить из буфера» с немедленным показом identicon |
| S4 Diff | Таблица old→new построчно;警предупреждения W-* | Кнопка «Отправить в μ» активна только при 0 ошибок |
| S5 Ожидание | «Подтвердите на устройстве…» + TTL-таймер демона | Результат Applied/Rejected с причиной |
| S6 История | Список DeltaChanged: ts, old_hash→new_hash | Read-only |

### 8.2. Правила UI

- Суммы вводятся в человекочитаемых единицах, конвертация в минорные — только через mu-policy (без float: парсинг decimal-строки в u128).
- Любая ошибка E-* рендерится у поля; W-* — жёлтой плашкой в S2 и повторно в S4.
- Пустое состояние (демон недоступен): S1 в режиме «offline-черновик», экспорт заблокирован, явный баннер.
- Никогда не отображать и не запрашивать: ключи, seed, адрес источника средств, содержимое Value.

## 9. Безопасность

### 9.1. Модель угроз и контрмеры

| Угроза | Контрмера | Где |
|---|---|---|
| Троянский Composer | Подпись+diff+биометрия только в демоне; данные diff в M9 берутся из proposal, не из UI | демон |
| Clipboard-подмена адреса | Identicon + укрупнённые 6+6 символов при вставке (S3); финальная сверка в M9 | C1+демон |
| TOCTOU | base_delta_hash; Rejected{Stale} с автоперезагрузкой текущей Δ | C4+демон |
| DoS демона мусором | len≤8К, hardened-парсер, 1 соединение, rate-limit 6 propose/мин | демон |
| Гомоглифы/би-ди в label (спуфинг diff) | E-LBL-01: запрет управляющих и bidi-символов; NFC-нормализация | mu-policy |
| Supply chain | ≤5 внешних crates, cargo-deny, lockfile, reproducible build, без CDN | сборка |
| Локальный вор черновиков | Δ не секрет (принято); опция encrypt_drafts | C3 |
| Другой пользователь ОС | Права 0600/DACL на сокет и каталог `$MU_HOME` | ОС |

### 9.2. Явные не-цели защиты
Скомпрометированная ОС/root, вредонос с правами пользователя, читающий память демона, физический доступ — вне модели (закрываются уровнем M4/платформой).

## 10. Ошибки и деградация

| Ситуация | Поведение Composer |
|---|---|
| Демон недоступен | Offline-режим черновика; retry Ping каждые 5 с; баннер |
| Rejected{Stale} | Тост «Δ изменилась извне», авто-GetPolicy, diff пересчитан, черновик сохранён |
| Rejected{HumanTimeout/Denied} | Черновик сохранён, S4 остаётся, повтор вручную |
| Обрыв сокета после Accepted | Poll GetPolicy: если delta_hash == предложенному → показать Applied |
| Повреждён файл черновика | Черновик отбрасывается с сообщением; текущая Δ из демона |

## 12. Сборка и дистрибуция

- Workspace: `mu/` (демон) + `mu-policy/` + `composer/` (tauri) + `composer-cli/`.
- Подпись бинарей: macOS notarization, Windows Authenticode, Linux — sha256+minisign-подпись релиза.
- Версионирование: semver; совместимость proposal v1 фиксируется контракт-тестом демон↔Composer в CI.
- Конфиг: `$MU_HOME/composer.toml` — socket_path, locale, encrypt_drafts.

## 14. Критерии приёмки (MVP)

1. На всех трёх ОС: изменить daily_limit через GUI → биометрия на демоне → GetPolicy возвращает новую Δ, в истории есть DeltaChanged.
2. Ошибки E-LIM-02, E-ADR-02, E-THR-01 воспроизводимо блокируют экспорт с сообщением у поля.
3. Гонка двух экземпляров Composer завершается ровно одним Applied и одним Rejected{Stale}.
4. Отключение сети устройства не влияет на работу (доказательство отсутствия внешних соединений — тест с запретом egress).
5. Троян-симуляция: модифицированный Composer, подменяющий адрес после S4, не приводит к применению — диалог M9 показывает адрес из proposal, владелец видит подмену.
