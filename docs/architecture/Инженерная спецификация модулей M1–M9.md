# Инженерная спецификация модулей M1–M9 (референс-язык Rust; для Node/TS сигнатуры зеркальны)

---

## M1 mu-core

**Назначение:** единственный владелец формата μ-объекта. Никто, кроме M1, не сериализует и не пишет μ на диск.

```rust
struct Mu { core: Core, omega: Omega, delta: SignedDelta, value: ValueRef, log_head: Hash }
struct Core { id: Uuid /*v7*/, owner_pubkey: P256Pub, created_at: u64, version: u16 }

fn load(path: &Path) -> Result<Mu, CoreErr>            // decode CBOR → verify COSE → verify checksum
fn save(mu: &Mu, path: &Path) -> Result<(), CoreErr>   // tmp + fsync(file) + rename + fsync(dir)
fn verify(mu: &Mu) -> Result<(), CoreErr>              // подписи: COSE(μ, ключ μ), COSE(delta, owner), checksum
fn reissue(old: &Mu, new_omega: Omega, vault: &Vault) -> Result<Mu, CoreErr>
```

- **Формат:** внешняя обёртка `COSE_Sign1(ES256)`; payload — CBOR-map с int-ключами (1=core, 2=omega, 3=delta, 4=value, 5=log_head). Δ — вложенный `COSE_Sign1` ключом владельца (два контура доверия).
- **Ошибки:** `enum CoreErr { Io, CborMalformed, SigMu, SigOwner, ChecksumMismatch, VersionUnsupported }`. Любая → объект не используется, runtime не стартует.
- **Инварианты:** μ ≤ 3 КБ; `reissue` = новый `id`, `version+1`, лог старого архивируется, изменение Ω другим путём невозможно.
- **Тесты:** roundtrip encode/decode; бит-флип любого байта → verify=Err; kill -9 во время save → на диске старая или новая версия, никогда «полверсии».

## M2 mu-omega

**Назначение:** stateless-фильтр «может ли μ вообще». Чистая функция, ноль I/O, ноль паник.

```rust
struct Omega { operations: Vec<Op>, connectors: Vec<ConnectorId>,
               max_ceiling: Amount, merchant_classes: Reserved }

fn check(intent: &Intent, omega: &Omega, gas_estimate: Amount) -> Decision
enum Decision { Allow, Deny(DenyReason) }
enum DenyReason { OpUnsupported, ConnectorUnknown, CeilingExceeded { asked: Amount, ceiling: Amount } }
```

- **Правило сумм:** `intent.amount + gas_estimate <= ceiling`, арифметика checked (переполнение = Deny, не паника). `Amount` — целые минорные единицы (u128), float запрещён во всём проекте.
- **Тесты:** таблица граничных случаев (ceiling, ceiling±1, u128::MAX); property-test: Deny стабилен при любом мусорном intent.

## M3 mu-delta

**Назначение:** политики момента + защита лимита от гонок. Резерв — до денег, снятие — только commit/rollback.

```rust
struct Delta { daily_limit: Amount, whitelist: HashSet<Address>, confirm_threshold: Amount }

fn check_and_reserve(i: &Intent, d: &Delta, log: &dyn LogRead) -> Result<Reservation, DeltaDeny>
fn commit(r: Reservation, log: &mut dyn LogWrite)
fn rollback(r: Reservation, log: &mut dyn LogWrite)
fn needs_human(i: &Intent, d: &Delta) -> bool          // amount > confirm_threshold
enum DeltaDeny { NotWhitelisted, WindowExceeded { spent: Amount, limit: Amount } }
```

- **Окно:** `spent = Σ(SETTLED ∪ PENDING) за последние 86400 с по timestamp'ам записей лога` (не системная дата). PENDING считается потраченным — это и есть резерв.
- **Адреса:** сравнение только в канонической форме (lowercase hex + chain_id); EIP-55-чексумма валидируется на входе в whitelist, не при сравнении.
- **Инвариант:** между `check_and_reserve` и `commit/rollback` не может пройти второй `check_and_reserve` (гарантируется однопоточностью M6, но M3 дополнительно держит флаг `in_flight` и возвращает `Busy` — защита от будущего рефакторинга).
- **Тесты:** два intent'а по 60% лимита — второй Deny; серия SETTLED на границе 24ч ± 1с; rollback возвращает ёмкость окна.

## M4 mu-vault

**Назначение:** граница секретов. Наружу — подписи и хэндлы, никогда байты ключей.

```rust
trait Vault {
    fn sign_mu(&self, digest: &[u8;32]) -> Result<P256Sig, VaultErr>;      // в железе
    fn tx_signer(&self) -> Result<TxSigner, VaultErr>;                     // scoped-хэндл
}
struct TxSigner(/* приватно: Zeroizing<Secp256k1Key> */);
impl TxSigner { fn sign(&self, sighash: &[u8;32]) -> Secp256k1Sig }        // RFC 6979
impl Drop for TxSigner { /* zeroize */ }
```

- **Платформенные бэкенды:** `AppleEnclave` (SecKey P-256, kSecAttrTokenIDSecureEnclave), `AndroidStrongBox` (Keystore, setIsStrongBoxBacked), `Tpm2` (ESAPI), `SoftVault` — только для тестов, за feature-флагом, в release-сборке компиляция с ним падает.
- **Ключ кошелька:** хранится как `AES-256-GCM(privkey, kek)`, где kek — non-exportable ключ железа; unwrap → `Zeroizing<>` → подпись → Drop. Время жизни plaintext-ключа — микросекунды, логировать его касание запрещено линтом (deny `Debug` на типе).
- **Ошибки:** `VaultErr { HwUnavailable, UserAuthRequired, WrapCorrupted }`; `WrapCorrupted` фатальна — runtime останавливается, средства недоступны до восстановления.
- **Тесты:** на CI — SoftVault, полный конвейер; на устройствах — smoke: sign_mu детерминирован (RFC 6979), unwrap после перезагрузки работает, дамп памяти после Drop не содержит ключа (best-effort тест).

## M5 mu-log

**Назначение:** WAL и источник истины для лимитов; hash-chain делает журнал невыдираемым.

```rust
struct Entry { seq: u64, prev_hash: Hash, ts: u64, kind: Kind, sig: P256Sig }
enum Kind { DeniedOmega{..}, DeniedDelta{..}, Pending{intent, chain_nonce},
            Settled{tx_hash, gas_paid}, Failed{reason}, Simulated{connector},
            DeltaChanged{old_hash, new_hash}, HumanDecision{approved: bool} }

fn append(&mut self, k: Kind) -> Result<Hash, LogErr>    // hash = SHA256(prev_hash ‖ cbor(entry))
fn verify_chain(&self) -> Result<(), LogErr>
fn pending(&self) -> Vec<&Entry>
fn window_sum(&self, now: u64) -> Amount                 // Σ Pending+Settled за 86400с
fn reconcile(&mut self, c: &dyn ConnectorStatus) -> Result<ReconcileReport, LogErr>
```

- **Носитель:** append-only файл, записи length-prefixed CBOR; fsync после каждой записи (частота платежей низкая — цена приемлема); повреждённый хвост при старте: обрезается ДО последней валидной записи, факт обрезки пишется отдельной записью.
- **reconcile:** для каждой Pending → `connector.status(chain_nonce/tx_hash)`; found→Settled, not found и nonce уже занят другой tx→Failed, сеть недоступна→остаёмся Pending и M6 не открывает M8.
- **Тесты:** verify_chain ловит удаление/перестановку/правку любой записи; kill -9 между Stripe-аналогом (отправкой tx) и append невозможен by design (append раньше) — тест подтверждает порядок; window_sum на синтетике 10⁴ записей < 10 мс.

## M6 mu-runtime

**Назначение:** оркестратор. Вся последовательность — в одном месте, модули не знают друг о друге.

```rust
fn start(cfg: Config) -> Result<Handle, StartErr>   // load μ → verify → verify_chain → reconcile → listen
fn submit(&self, i: SignedIntent) -> Ticket
fn status(&self, t: Ticket) -> IntentStatus
enum IntentStatus { Queued, AwaitingHuman{deadline}, Executing, Settled{tx}, Denied{reason}, Failed{reason} }
```

- **Конкурентность:** один worker-поток, вход — `mpsc`-канал ёмкостью N (переполнение → мгновенный `Denied(Busy)` без очереди-на-диске). Конвейер строго: Ω → Δ.reserve → [human] → Log.Pending → Connector.execute → Log.Settled/Failed + Δ.commit/rollback.
- **Таймауты:** human — TTL из конфига (15 мин); execute — 120 с на финальность, по истечении статус остаётся Pending и уходит в reconcile-цикл (не Failed! деньги могли уйти).
- **Деградация:** любая ошибка verify на старте → процесс завершён с кодом ≠0 и человекочитаемым отчётом; частичный старт запрещён.
- **Тесты:** интеграционный на SoftVault+bank_stub: 100 конкурентных submit → сумма Settled ≤ daily_limit всегда; chaos-тест: убийство процесса в каждой точке конвейера → после рестарта инварианты денег/лога сходятся.

## M7 mu-connect

**Назначение:** единственная точка контакта с деньгами внешнего мира.

```rust
trait Connector: Send {
    fn quote(&self, i: &Intent) -> Result<Fee, ConnErr>;            // gas_estimate для Ω
    fn execute(&self, i: &Intent, s: TxSigner) -> Result<TxRef, ConnErr>;
    fn status(&self, r: &TxRef) -> Result<TxStatus, ConnErr>;
}
enum TxStatus { Pending, Settled { block: u64 }, Failed { reason: String } }
```

**M7a crypto (USDC / Base):**

- `execute`: nonce = max(локальный из Log, eth_getTransactionCount(pending)); сборка ERC-20 `transfer(to, amount)`; EIP-1559 (maxFee = base×2 + tip); подпись через TxSigner; `eth_sendRawTransaction` в оба RPC; успех = хотя бы один принял.
- `status`: `eth_getTransactionReceipt` с обоих RPC; расхождение ответов → Pending + метрика тревоги; Settled при N подтверждений (N=1 для L2 c быстрой финальностью, конфигурируемо).
- **Ошибки:** различать `ConnErr::Rejected` (nonce-конфликт, insufficient funds — можно Failed сразу) и `ConnErr::Unknown` (таймаут сети — ТОЛЬКО Pending, никогда Failed).
- **Тесты:** Anvil/Hardhat-форк: happy path, повтор с тем же nonce, RPC₁ лжёт о receipt.

**M7b/M7c stubs:** `execute` → `TxRef::simulated(uuid)`, задержка 50–500 мс (конфиг), опц. инъекция ошибок по вероятности — для chaos-тестов M6. Возвращаемый Kind в лог — всегда `Simulated`, чтобы стаб-платежи не попали в window_sum. ~40 строк.

## M8 mu-gate

**Назначение:** периметр. Всё недоверенное умирает здесь.

```rust
fn listen(path: &Path, allow: &AllowList, sink: Sender<SignedIntent>) -> !
struct WireIntent { v: u16, recipient: String, amount_minor: u128, asset: String,
                    purpose: String /*≤256B*/, agent_id: String, nonce: u64, ts: u64 }
// провод: len(u32 LE) ‖ cbor(WireIntent) ‖ ed25519_sig(agent_key, cbor)
```

- **Транспорт:** unix socket `0600` (Windows: named pipe + DACL). Проверки по порядку и с ранним выходом: длина ≤ 4 КБ → CBOR валиден → agent_id ∈ allowlist → подпись Ed25519 → `|ts − now| ≤ 60с` и nonce > последнего от этого агента (анти-replay, окно nonce'ов в памяти) → rate-limit token-bucket (конфиг, дефолт 10/мин на агента).
- **Ответ агенту:** `{ticket}` сразу, дальше — polling `status(ticket)` тем же сокетом. Никаких деталей Δ/Ω/адресов источника в любых ответах и ошибках (единый непрозрачный `Denied{code}`).
- **Тесты:** fuzzing входного парсера (cargo-fuzz); replay того же пакета → Deny; подпись чужим ключом → Deny; slow-loris (байты по одному) → таймаут чтения 5 с.

## M9 mu-human

**Назначение:** канал владельца: подтверждения и стекло журнала.

```rust
fn confirm(req: ConfirmReq, ttl: Duration) -> HumanDecision   // Approved | Denied | Timeout
fn view_log(f: LogFilter) -> Vec<EntryView>                   // read-only проекция M5
fn edit_delta(new: Delta) -> Result<(), HumanErr>             // биометрия → подпись owner → M1.save
```

- **Диалог подтверждения** обязан показывать: получатель (полный адрес + label из whitelist), сумма+asset, gas, агент, остаток дневного лимита. Платформы: LocalAuthentication / BiometricPrompt(CryptoObject) / Windows Hello. Биометрия криптографически связана с owner-ключом (auth-required key в keystore), а не просто «диалог показан».
- **Timeout:** по TTL решение = Timeout, M6 делает rollback; повторный intent — только новым запросом агента.
- **edit_delta:** diff показывается владельцу до биометрии; запись `DeltaChanged` в лог с хешами старой/новой Δ.
- **Тесты:** UI-автотест таймаута; edit_delta без валидной биометрии невозможен (мок keystore отклоняет подпись).

## Сквозные требования

| Требование              | Норма                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| Деньги                  | Только целые минорные единицы (u128), никаких float                                      |
| Логи приложения (не M5) | Запрещены: ключи, адрес источника, содержимое Δ; intent'ы — только хеш                   |
| Ошибки                  | `thiserror`-иерархия на модуль; паника в release = баг                                   |
| Время                   | Единый `Clock`-trait, инжектится (тестируемость окна 24ч)                                |
| Сборка                  | M2, M3 — `no_std`-совместимые по возможности (чистота); SoftVault не линкуется в release |
| CI-гейт                 | unit + property (M2/M3) + fuzz (M8) + chaos (M6) + coverage ядра ≥ 80%                   |

✓ M1–M9 описаны инженерно: структуры, сигнатуры, ошибки, инварианты, тесты, сквозные нормы
